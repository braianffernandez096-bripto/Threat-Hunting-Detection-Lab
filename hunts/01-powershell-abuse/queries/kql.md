# 🔍 KQL Queries — PowerShell Abuse Hunt

## 📌 Overview

This document contains the KQL (Kibana Query Language) queries used during the PowerShell Abuse hunt.

Each query has a specific investigative purpose and should be interpreted alongside the surrounding telemetry and analyst context.

Behavioral analysis is always preferred over relying on a single event.

---

# Query 1 — PowerShell Process Execution

## 🎯 Objective

Identify all PowerShell executions recorded by Sysmon.

### KQL

```kql
event.code:1 AND process.name:powershell.exe
```

### Detects

- PowerShell process creation.
- User-initiated PowerShell sessions.
- Script execution.

### Expected Telemetry

- Sysmon Event ID 1
- Process Name
- Parent Process
- Command Line
- User

### Investigation Notes

Review:

- Parent process
- Command-line arguments
- User account
- Execution path

---

# Query 2 — Encoded PowerShell Commands

## 🎯 Objective

Identify encoded PowerShell execution.

### KQL

```kql
event.code:1 AND process.command_line:*EncodedCommand*
```

### Detects

- Base64 encoded commands
- Obfuscated PowerShell execution

### Expected Telemetry

- Full command line
- Parent process
- User
- Timestamp

### Investigation Notes

Encoded commands are frequently used to evade basic detection.

Always review the complete command line.

---

# Query 3 — PowerShell Network Connections

## 🎯 Objective

Identify network activity generated by PowerShell.

### KQL

```kql
event.code:3 AND process.name:powershell.exe
```

### Detects

- HTTP
- HTTPS
- SMB
- DNS
- Other outbound connections

### Expected Telemetry

- Destination IP
- Destination Port
- Protocol
- Process GUID

### Investigation Notes

Investigate:

- External IPs
- Unexpected destinations
- Multiple outbound connections

---

# Query 4 — PowerShell Download Activity

## 🎯 Objective

Identify PowerShell download attempts.

### KQL

```kql
event.code:1 AND process.command_line:(
    *Invoke-WebRequest*
    OR *DownloadString*
    OR *Net.WebClient*
)
```

### Detects

Common download cradles used by attackers.

### Investigation Notes

Review:

- Download source
- Parent process
- Destination host
- Download frequency

---

# Query 5 — Suspicious PowerShell Execution Path

## 🎯 Objective

Detect PowerShell launched from unusual locations.

### KQL

```kql
event.code:1
AND process.name:powershell.exe
AND process.executable:*Users*
```

### Detects

Potential execution from:

- User profile
- Downloads
- Temp folders

### Investigation Notes

PowerShell normally executes from:

C:\Windows\System32\WindowsPowerShell\

Execution from user-controlled paths should be investigated.

---

# Analyst Recommendations

During PowerShell investigations always verify:

- Parent process
- Child processes
- Network activity
- Authentication context
- Command line
- Execution path
- Frequency of execution

Never rely on a single event to determine malicious activity.

Behavior correlation provides significantly higher confidence.
